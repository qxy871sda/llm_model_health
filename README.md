# LLM 模型健康度/成功率统计插件

统计并展示 MaiBot 使用的 LLM 模型健康度：窗口内的请求成功率（默认只开这一项），并可按需开启失败原因、模型自身耗时与历史汇总。

- 插件版本：`1.2.0`
- 已验证环境：MaiBot `1.3.5` + `maibot-plugin-sdk` `2.10.0`
- 声明能力：`send.text`、`send.forward`、`config.get`、`database.query`、`statistics.local.models`

## 功能

- **近期模型健康度（默认开启）**：按统计窗口展示每个模型的请求数、成功数、失败数、成功率、整轮耗时与 token 用量。
- **失败原因归因（默认关闭）**：从宿主 Prompt 快照的逐次尝试里汇总失败原因（超时 / 429 限流 / HTTP 4xx / 5xx / 空回复 / 连接失败），并列出涉及的模型。
- **模型自身耗时（默认关闭）**：区分「整轮请求耗时」与「模型自身耗时」，避免把同一次请求里其它模型的失败等待算到成功模型头上。
- **历史累计汇总（默认关闭）**：读取宿主本机统计，展示最近 N 天每个模型的请求数、token 用量与平均整轮耗时。
- **模型费用（默认关闭）**：历史汇总里的累计费用单独开关控制，默认不展示。
- **管理员权限**：仅指定的管理员 QQ 允许调出统计报告；留空时所有人均不可调用。
- **自定义指令触发**：支持自定义调出统计数据的指令（默认为 `/模型健康度`），避免与其他插件指令冲突。
- **合并转发发送**：报告通过合并转发（Forward）消息发送，阅读体验清晰整洁。

## 统计口径（为什么数据可信）

| 指标 | 数据来源 | 覆盖范围 | 说明 |
| --- | --- | --- | --- |
| 成功数 / token / 整轮耗时 / 费用 | 宿主 `llm_usage` 表（`database.query` 能力） | **全部模块** | 每次成功完成的逻辑请求都会入账，按窗口时间过滤；费用展示需开启「显示模型费用」 |
| 失败数 | 宿主 WARNING 日志 `模型 '<分配名>' 尝试失败，切换到下一个模型` | **全部模块** | 每次模型尝试失败都会输出，不受文件日志级别影响 |
| 成功率 | `成功 / (成功 + 失败)` | — | 不依赖 DEBUG 行，也不使用 `max()` 之类的启发式补偿 |
| 失败原因 / 自身耗时 | 宿主 Prompt 快照 `generation_attempts[]` | 仅覆盖会写预览的模块 | 只作为增量信息，不参与成功率计算（默认关闭） |
| 历史汇总 | `statistics.local.models` | 全部模块（仅成功请求） | 没有失败数据，因此不展示成功率（默认关闭） |

两种耗时口径：

- **整轮耗时**：宿主 `llm_usage.time_cost`，覆盖模型选择、Prompt 构建、同一次请求里所有失败尝试与重试间隔，属于「一次逻辑请求」的墙钟时间。
- **自身耗时**：Prompt 快照里成功尝试的 `duration_ms` 中位数，只衡量该模型自己花的时间。

## 数据来源与私有实现依赖（失效风险）

插件能走官方能力的部分**全部走官方能力**：

| 数据 | 来源 | 是否官方接口 |
| --- | --- | --- |
| 成功数 / token / 整轮耗时 / 费用 | `database.query`（`ModelUsage` → `llm_usage` 表，只读 get 查询） | ✅ 官方能力（字段名为宿主数据库结构；费用展示默认关闭） |
| 历史汇总（请求数 / token / 平均耗时 / 费用） | `statistics.local.models` | ✅ 官方能力（默认关闭） |
| 发送报告 / 读取机器人昵称等 | `send.forward` / `send.text` / `config.get` | ✅ 官方能力 |
| 供应商模型标识 → 分配名映射 | 复用上面 `llm_usage` 记录里的 `model_name` + `model_api_provider_name` + `model_assign_name` | ✅ 官方能力（**不需要读宿主模型配置**） |
| **失败数** | 宿主日志 WARNING 文案 | ❌ 只能私有实现（宿主没有失败统计能力/事件/数据表） |
| 失败原因 / 模型自身耗时 | 宿主 Prompt 快照 | ❌ 只能私有实现（仅覆盖写预览的模块，默认关闭） |

因此剩余的私有实现依赖只有 3 类（位置固定在 `host_logs.py` / `host_snapshots.py`，每个常量都带「私有实现依赖」注释）：

1. **目录布局**：插件通过 `ctx.paths.data_dir` 严格校验 `<宿主根目录>/data/plugins/<插件ID>` 后上溯定位日志目录（SDK 只提供 `data_dir`，不提供宿主根目录）。布局不符会显式抛错，不会静默读错目录。
2. **日志**：文件名 `logs/app_*.log.jsonl`、失败文案 `模型 '<分配名>' 尝试失败，切换到下一个模型`（`src/llm_models/utils_model.py` 的 WARNING）、以及两种时间戳格式（主进程 ISO-8601 UTC / Runner `MM-DD HH:MM:SS`）。
3. **Prompt 快照**：`logs/maisaka_prompt/<类别>/<会话>/<毫秒时间戳>.json` 与 `llm_error/...` 里的 `generation_attempts[]`（`model` / `provider` / `started_at` / `duration_ms` / `status` / `error`）；`enable_snapshot_detail=false`（默认）时**完全不读取这一类**。

一旦宿主改动上述任一内容，插件不会静默给出错误结论：

- 找不到日志目录 → 报告顶部提示「失败数与成功率不可用」；
- 读取预算不足 / 成功记录达到上限 → 提示窗口未被完整覆盖，并给出需要调高的配置项；
- 日志文案失效（失败一条都没匹配到，但 Prompt 快照里存在失败尝试）→ 通过**快照交叉校验**提示日志文案或日志级别可能已变更。

> 未来若宿主把 `POST_LLM` / `AFTER_LLM` 事件真正发射出来（当前仅在 `src/core/types.py` 定义、无发射点），或新增「模型尝试成功/失败统计」能力，第 2 类依赖即可删除。

## 插件不会做什么

本插件只做「读统计元数据 + 发一条报告」，具体边界如下（均可在源码中核对）：

- **不联网**：插件自身不发起任何网络请求（源码内没有 `requests` / `aiohttp` / `httpx` / socket 调用）。报告是交给宿主的 `send.*` 能力发送的，平台通信由 MaiBot 与适配器负责。
- **不上传**：不采集、不上传任何数据；不读取聊天内容。只读取模型名、请求数、token、耗时、费用、错误原因摘要这类统计元数据，以及日志中的失败事件行。即使开启 Prompt 快照解析，也只取 `generation_attempts` 字段（模型名/供应商/耗时/状态/错误摘要），**不读取快照里的 Prompt 与消息内容**。
- **不执行命令**：不调用子进程、shell 或系统命令（源码内没有 `subprocess` / `os.system`）。
- **不修改任何东西**：对日志与快照文件**只读**打开（`open("r")` / `open("rb")`）；数据库只通过官方 `database.query` 的 `get` 形式读取；不写、不改、不删宿主配置、数据库、聊天流，也不建表。插件自己也不在 `data_dir` 里写任何文件（无状态文件）。
- **不额外消耗模型额度**：不调用 `llm.*` 能力，不会产生任何额外 token 或费用。
- **不常驻、不轮询**：没有任何后台任务或定时器（无 `asyncio.create_task`），只在你手动触发指令时执行一次，读完即结束。
- **只申请 5 项已声明能力**：`send.text`、`send.forward`、`config.get`、`database.query`、`statistics.local.models`；未声明的能力调用会被宿主拒绝，插件也不会尝试。

## 指令

- `/模型健康度`（默认）：调出当前的模型健康度报告。
  - *注：若在配置中修改了指令触发器，请使用自定义指令；修改后需重启插件生效。*

## 配置项

可通过 `config.toml` 文件或 WebUI 设置页面修改（**默认只开「近期模型健康度」，其余全部关闭**）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | `true` | 是否启用此统计插件 |
| 管理员 QQ | 空 | 有权限调出统计数据的管理员 QQ，多个用中/英文逗号分隔；留空时不允许任何人调用 |
| 触发指令 | `/模型健康度` | 调出统计数据的指令 |
| 统计范围类型 | `minutes` | `minutes` 按分钟，`count` 按请求次数 |
| 统计范围数值 | `60`（配置文件值；代码内默认 `30`） | `minutes` 时代表最近 N 分钟；`count` 时代表窗口内最近 N 次模型请求尝试（成功与失败一起计数） |
| 成功记录读取上限 | `5000` | 窗口内最多读取多少条 `llm_usage` 记录，窗口较长或请求量很大时调高 |
| 失败日志读取预算(MB) | `32` | 扫描失败日志的最大读取量，预算不足时报告会提示窗口未完整覆盖 |
| 近期模型展示条数 | `15` | 近期运行状态里最多展示多少个模型 |
| 失败原因与自身耗时 | `false` | 是否从宿主 Prompt 快照读取失败原因与模型自身耗时（**默认关**） |
| 失败原因条数 | `5` | 失败原因最多展示多少条（仅在上一项开启时生效） |
| 启用历史模型汇总 | `false` | 是否展示历史请求数、token 用量与平均耗时（**默认关**） |
| 历史汇总天数 | `365` | 历史汇总范围（1~365 天） |
| 显示模型费用 | `false` | 是否在历史汇总中展示每个模型的累计费用（**默认关**，需先开历史汇总） |

## 报告示例

默认配置下报告为 3 条转发消息；开启「失败原因与自身耗时」后插入一条「失败原因」，开启「历史模型汇总」后追加一条「历史累计统计」：

```
【第 1 条 · 标题】
📊 MaiBot LLM 模型健康度报告
━━━━━━━━━━━━━━━━━━━━━━
⏰ 统计窗口：最近 60 分钟
🔢 窗口内请求：905 次（成功 513 | 失败 392 | 成功率 56.7%）

【第 2 条 · 近期运行状态】
- **glm-5.3-flash**：请求 80 | 成功 80 | 失败 0 | 成功率 100.0% | 整轮耗时 4.66s | 522.0k tokens
- **deepseek-v4.1-flash**：请求 56 | 成功 54 | 失败 2 | 成功率 96.4% | 整轮耗时 13.41s

【第 3 条 · 统计口径】
**统计口径**
- 成功率 = 窗口内成功请求 / (成功 + 失败尝试)
- 成功数：宿主 llm_usage 表，覆盖全部模块
- 失败数：宿主 WARNING 日志「尝试失败，切换到下一个模型」，覆盖全部模块
- 自身耗时与失败原因：宿主 Prompt 快照（需开启「失败原因与自身耗时」），仅覆盖会写预览的模块
- 历史汇总：宿主本机统计（需开启「启用历史模型汇总」），只含成功请求

（可选）【· 失败原因】开启「失败原因与自身耗时」后出现，紧跟「近期运行状态」
- HTTP 403（鉴权/权限） × 107（gemini-3.1-flash-lite、gpt-oss:120b）
- 429 限流 × 73（MiniMax-M2.7-highspeed、MiniMax-M3）
- 超时 × 37（qwen3.8-flash-next-262k、MiniMax-M3.1-Flash）

（可选）【· 历史累计统计】开启「历史模型汇总」后出现；费用需再开「显示模型费用」
- **deepseek-v4-pro**：请求 2440 次 | 整轮耗时 24.85s | 10.51M tokens
```

## 限制与已知行为

- 失败原因与自身耗时依赖宿主 Prompt 快照，只有会写预览的模块（回复、表达/黑话学习、情绪、行为等）才有数据；`A_Memorix.*` 等模块没有快照，因此这两项**不会**参与成功率统计，且默认关闭。
- 失败数按「模型尝试」计数，成功数按「逻辑请求」计数：一次请求里失败 2 个模型后成功，会记为 2 次失败 + 1 次成功，成功率即 `成功 / 全部尝试`。
- `count` 模式把成功与失败按时间合并后截取最近 N 条，窗口起点即第 N 条尝试的时间。
- 历史汇总只包含成功完成的请求，因此不展示成功率；报告窗口与历史汇总的天数相互独立。
- 插件不提供「请求数趋势」统计（已在 1.2.0 移除）；需要趋势图可以看 MaiBot WebUI 的统计页面。
- 插件自身不联网、不上传、不执行命令、不修改任何文件与数据（详见上文「插件不会做什么」）。

## 版本与变更

### 1.2.0（当前）

- 可选模块默认关闭：「失败原因与自身耗时」「历史模型汇总」默认均不启用，报告默认只包含标题页、近期运行状态、统计口径。
- 新增「显示模型费用」独立开关（默认关闭），费用不再随历史汇总一起展示。
- 移除「请求数趋势」统计，并移除对应能力依赖 `statistics.local.model_trend`。
- 成功率口径改为「官方 `llm_usage` 成功数 + 宿主 WARNING 日志失败数」，不再依赖 DEBUG 日志行，也不再用 `max()` 启发式补偿。
- 私有实现依赖收敛为 3 类（目录布局 / 日志 / 可选的 Prompt 快照），并集中到 `host_logs.py` 与 `host_snapshots.py`。
- 新增失效告警：找不到日志目录、读取预算不足、成功记录达到上限、以及「日志文案失效但快照仍有失败」的快照交叉校验，都会在报告顶部显式提示。
- 新增「插件不会做什么」边界说明（不联网 / 不上传 / 不执行命令 / 不修改任何文件与数据）。

### 1.0.5（先前版本）

- 仅提供「近期运行状态」（尝试数取自 DEBUG 日志行 `选择请求模型:`，失败数取自 WARNING 日志）与「历史模型汇总（含费用）」。
- 日志扫描限定为按修改时间最新的 5 个文件、每个文件尾部 100KB；时间戳仅按 `MM-DD HH:MM:SS` 解析。
- 没有任何失效告警：宿主日志文案/格式变化时会静默给出不完整或错误的成功率。
